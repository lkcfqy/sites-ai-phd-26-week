# 变式任务：从失败、修复到评阅

只需要 Python 3 标准库和 CPU。先阅读 `assessment.py`，再放到新建的学习目录。脚本不联网、不装依赖、不使用 GPU。它会执行你目录里的 `learner.py`，因此只运行你已经阅读、决定信任的代码；10 秒超时不是安全沙箱。

## 第一次练习

```sh
python3 assessment.py create --family trace --seed 104729 --directory task-trace-104729
python3 assessment.py check --directory task-trace-104729 --output trace-before.json
```

`create` 拒绝覆盖现有目录；`check` 拒绝覆盖已有结果。先打开 `task.json` 阅读契约，再打开 `learner.py`。起始代码故意有缺陷，第一次出现 `passed: false` 是预期。JSON 中每项保留输入、实际结果、预期结果与异常类型。

以日志任务为例，先手算 `[10,20,100]` 的平均数是 43.33，而 nearest-rank p95 是 100；失败请求的耗时仍要报告，但不应混入成功请求分位数。不要通过删除失败用例“修好”统计。修复一项原因，写自己的回归，再执行：

```sh
python3 assessment.py check --directory task-trace-104729 --output trace-after.json
```

把 before 和 after 分别导入网站“变式评测”。第一份写出假设、失败输入和未验证事项；第二份用“根据这次结果建立重试”关联。记录修改行、为什么改、哪个反例验证修复，最后写 2–4 句英文交接。

## 三种契约与先修

| family | 先修 | 要解决的真实编程问题 | 变式 |
| --- | --- | --- | --- |
| trace | Python 列表、字典、排序、异常，成功/失败统计 | 验证日志、保留错误、只对成功项算 nearest-rank p95 | 长尾、零耗时、全失败、重复 ID、非法数值 |
| partition | 整数除法、循环、半开区间，线程分工 | n 个元素按 workers 分片，不遗漏、不重复、不生成空片 | 非整除、n=0/1、线程多于元素、资源上限 |
| decision | 字典、筛选、排序，质量与预算 | 先满足质量/SLO/内存，再选最低延迟，平局按名称 | 无可行方案、临界等号、质量退化、超内存 |

partition 的规范化输出把余数依次分给最前面的片段，所有片段按起点递增。线程任务只检查分片函数，**不证明真实并发没有竞态**；还需完成 C++ 线程包。decision 使用合成候选指标，**不证明真实模型质量**；还需真实模型与服务实验。

## 下一次变式与评阅

请同伴在你保存代码后选择一个新种子（1–2147483647）并创建新目录，把你自己的实现复制过去，保留新命令和输出。题目与生成器公开，不声称隐藏题或防作弊。新条件可以更换任务类型；不同任务另记尝试，不把一类测试当作全部能力。

评阅必须写依据：

1. **正确性**：实际跑过哪些正常/边界/非法输入？哪些仍失败？
2. **复现与测量**：是否从新目录按 README 重跑？原始结果完整吗？计时和单位是否明确？
3. **诊断**：最小失败输入、根因与修复是否相连？有没有排除另一个假设？
4. **迁移**：换种子/规模/资源预算后如何？什么结论不能迁移？

有未检查或待改进项时选择“先修订”。全部检查后也只建议“换新条件再做”，不会自动认证独立能力。网站区分自评与当前账号记录的同伴反馈；它没有认证评阅者身份。请用代称，别填邮箱、证件或私人信息。

维护者可以用 `check --reference` 核查评分器；结果会标记 `source_kind: reference`，不能提交为学习者独立实现。不要替学习者把 TODO 全填好后计为个人成绩。


## 题库版本与执行诊断

新任务默认 `case_version: 2`。日志用例含 26 条成功记录，最近秩 p95 不再总等于最大值；方案选择包含延迟/内存都合格、仅质量不合格的候选。最大值代替 p95、遗漏质量筛选必须被检查器抓住。旧 `task.json` 没有版本时按 v1 重放；已有尝试保留并注明旧版覆盖较弱。要补当前验收应创建新 v2 任务，不重写旧记录；`create --case-version 1` 仅用于历史复现。

学习者的普通 `print()` 和 stderr 调试文字与机器 JSON 分流。每路诊断保留有界首尾并标明截断；语法错误保留 Python traceback 和行号。错误、超时或机器报告格式不正确时，命令以 2 退出，但仍新建 `passed: false`、空测试列表和具体 execution 状态的失败原件，供网页保存/修订。没有把未执行用例伪造成通过。默认 10 秒，可用 `check --timeout-seconds 0.5` 在已审阅的短任务上验证超时路径；最大仍为 10 秒。

正常执行但逻辑断言失败保留完整用例，CLI 正常保存结果；不因此退出 2。`stdout` 现在只输出机器摘要，学习者调试文字在原件的 execution.stdout 中。代码评测和其中的质量/延迟数字使用合成题设，不代表 GPU 实测或真实 LLM 质量。
